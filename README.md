# ПОЛКА — интернет-магазин с доставкой в ПВЗ Ozon

Готовый магазин: 100 товаров в 8 категориях, корзина, оформление заказа с выбором пункта выдачи Ozon,
автоматический расчёт доставки, интеграция с облачной кассой (54-ФЗ) и админка для остатков и цен.

**Стек:** Python 3 (только стандартная библиотека) + SQLite + ванильный JS. Зависимостей нет — `pip install` не нужен.

```
python3 app.py        →  http://localhost:8000        (витрина)
                      →  http://localhost:8000/admin  (админка, пароль admin123)
```

## 3. Быстрый старт

```bash
cd polka
cp .env.example .env        # и отредактируйте (пароль админки, название, реквизиты)
python3 app.py
```

- Витрина — `http://localhost:8000`
- Админка — `http://localhost:8000/admin`

Тестовый сценарий: добавьте товар в корзину → «Оформить заказ» → заполните имя и телефон →
выберите город и ПВЗ → появится стоимость доставки и итог → «Оплатить заказ» →
на странице заказа кнопка «Оплатить» проводит демо-платёж и меняет статус на «Оплачен».

## 4. Как менять остатки, цены и заказы

**Админка** (`/admin`, пароль из `ADMIN_PASSWORD`):

- **Сводка** — выручка, число заказов, ожидают оплаты, что заканчивается.
- **Товары и остатки** — таблица всех 100 позиций: правите цену и остаток прямо в строке → «Сохранить».
  Кнопка **«Остаток всем»** выставляет одинаковый остаток на весь каталог (например, 100 шт.).
  Поиск по названию и фильтр по категории.
- **Заказы** — последние 200 заказов: состав, ПВЗ, контакты, оплата, смена статуса
  (Ждёт оплаты → Оплачен → Собирается → В пути → Получен → Отменён). Отмена возвращает товар на склад.

**Начальные данные:** 100 шт. каждой позиции, цены из вашего списка (округлены до «красивых», со старой ценой для скидки).

**Как добавить новый товар** (пока через файл — админка правит только цену и остаток):
откройте `seed_catalog.py`, добавьте строку в список `P` в формате
`(slug, название, подкатегория, цена, старая цена, эмодзи, вес кг, описание, [буллеты])`,
запустите `python3 seed_catalog.py` — файл `data/catalog.json` перегенерируется,
а при следующем старте `app.py` добавит новые товары в базу (существующие остатки не перезапишутся).

## 5. Подключение Ozon (ПВЗ и доставка)

Сейчас: `OZON_MODE=demo` — 89 демо-ПВЗ в 23 городах и расчёт по тарифу
(база 199 ₽ + 39 ₽ за кг свыше 1 кг, бесплатно от 7 000 ₽). Всё это задаётся в `.env`.

Что нужно для реальных данных:

1. **Кабинет Ozon Seller** → настройки → **API**: получите `Client-Id` и `Api-Key`.
2. В `.env`:
   ```
   OZON_MODE=api
   OZON_CLIENT_ID=123456
   OZON_API_KEY=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
   ```
3. Список ПВЗ и стоимость доставки Ozon отдаёт партнёрам на схеме **FBS / realFBS**
   (Ozon Доставка). Напишите менеджеру Ozon, что вам нужен доступ к:
   - списку пунктов выдачи (`/v1/delivery/point/list`);
   - расчёту стоимости доставки до ПВЗ (`/v1/delivery/check`);
   - созданию отправления и трекингу (`/v2/posting/fbs/*`).

Точки правки собраны в одном файле — `integrations/ozon.py`:

- `_api_request()` — авторизация и один POST в Ozon Seller API;
- `get_pvz()` — список и фильтрация пунктов (если API недоступен, автоматически берёт локальный `data/pvz.json`);
- `calc_delivery()` — расчёт стоимости; при ошибке API откатывается на тариф, чтобы витрина не падала;
- `track_order()` — статус и трек-номер отправления.

Пока договора нет — можно оставить demo: стоимость доставки всё равно считается и добавляется к заказу,
просто по вашей тарифной сетке. ПВЗ в `data/pvz.json` можно заменить реальной выгрузкой
(структура полей: `id, city, address, type, icon, workHours, maxWeight, maxDimension`).

## 6. Подключение оплаты и облачной кассы (54-ФЗ)

В `.env` выберите провайдера: `PAYMENT_PROVIDER=yookassa | cloudpayments | robokassa | demo`.

### Вариант А. ЮKassa (рекомендую — чек делается сам)
1. Зарегистрируйте магазин на [yookassa.ru](https://yookassa.ru), добавьте магазин.
2. **Интеграция → Ключи API**: скопируйте `shopId` и `secret key`.
3. Включите **онлайн-кассу** в личном кабинете (ЮKassa работает с АТОЛ Онлайн / OrangeData / МодульКасса — выбираете и подключаете там же).
4. Заполните `.env`:
   ```
   PAYMENT_PROVIDER=yookassa
   YOOKASSA_SHOP_ID=123456
   YOOKASSA_SECRET_KEY=live_xxxxxxxxxxxxxxxx
   SHOP_URL=https://ваш-домен.ru
   VAT_CODE=1        # 1 — без НДС (УСН), 3 — НДС 20%
   SNO=usn_income    # ваша система налогообложения
   ```
5. Вебхук для статуса оплаты: в кабинете ЮKassa → Интеграция → HTTP-уведомления →
   URL `https://ваш-домен.ru/api/payments/webhook`, события `payment.succeeded`, `payment.canceled`.

Код уже формирует фискальный чек (`integrations/kassa.py → build_receipt`): наименование, количество,
сумма, ставка НДС, признак предмета расчёта (`commodity`), отдельная позиция «Доставка» (`service`),
email/телефон покупателя. Чек уходит в ОФД вместе с платежом, покупателю — на email.

### Вариант Б. CloudPayments
```
PAYMENT_PROVIDER=cloudpayments
CLOUDPAYMENTS_PUBLIC_ID=pk_xxxx
CLOUDPAYMENTS_API_SECRET=xxxx
```
В личном кабинете включите онлайн-кассу и укажите ставку НДС / СНО. Чек передаётся в поле `Receipt`.
Уведомления: URL тот же, проверка подписи `Content-HMAC` уже реализована.

### Вариант В. Robokassa
```
PAYMENT_PROVIDER=robokassa
ROBOKASSA_LOGIN=...
ROBOKASSA_PASSWORD1=...
ROBOKASSA_PASSWORD2=...
```
Чек передаётся в параметре `Receipt`. Result URL: `https://ваш-домен.ru/api/payments/webhook`.

### Отдельная облачная касса
Если касса не встроена в платёжный сервис, заполните `FISCAL_PROVIDER` / `FISCAL_TOKEN` / `FISCAL_GROUP_ID`
и вызовите `kassa.build_receipt()` в своём адаптере — объект чека универсальный.

### Юридический минимум
- ИП/ООО + **онлайн-касса** (54-ФЗ) — чек обязателен при расчётах с физлицами.
- Заполните `SELLER_NAME`, `SELLER_INN`, `SELLER_EMAIL` — они попадают в подвал сайта и чек.
- На сайте уже есть страницы «Публичная оферта», «Политика конфиденциальности», «Возврат» — приведите текст под себя.
- Проверьте настройку **СНО** и **ставки НДС** с бухгалтером: неверный `VAT_CODE` = неверный чек.

## 7. Публикация сайта

### Render.com (бесплатно, 5 минут)
1. Загрузите папку в репозиторий GitHub.
2. Render → **New → Web Service** → выберите репозиторий.
3. Build Command: пусто. Start Command: `python3 app.py`.
4. В **Environment** задайте `ADMIN_PASSWORD`, `SHOP_URL`, ключи оплаты.
5. Готово: `https://polka-shop.onrender.com`. Файл `render.yaml` позволяет развернуть через **Blueprint**.

> На free-тарифе сервис засыпает после 15 минут простоя, а файловая система сбрасывается при передеплое.
> Для боевого магазина: тариф с диском или внешняя БД (Postgres).

### Docker (Railway, Fly.io, свой сервер)
```bash
docker build -t polka .
docker run -d -p 8000:8000 --env-file .env \
  -v $(pwd)/data:/app/data --name polka polka
```

### Свой VPS (полный контроль, свой домен)
```bash
scp -r polka user@server:/opt/
ssh user@server
cd /opt/polka && cp .env.example .env && nano .env
python3 app.py     # проверить, что запускается
```
systemd-юнит `/etc/systemd/system/polka.service`:
```ini
[Unit]
Description=Polka shop
After=network.target

[Service]
WorkingDirectory=/opt/polka
ExecStart=/usr/bin/python3 /opt/polka/app.py
EnvironmentFile=/opt/polka/.env
Restart=always
User=www-data

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl enable --now polka
```
Домен и HTTPS: nginx как reverse-proxy на `127.0.0.1:8000` + `sudo certbot --nginx -d ваш-домен.ru`.

## 9. Частые вопросы

**Товары — эмодзи. Как поставить фото?**
У товара есть поле `image`. Положите файлы в `static/uploads/`, затем:
```bash
sqlite3 data/shop.db "UPDATE products SET image='/uploads/powerbank.jpg' WHERE id=7;"
```
Витрина автоматически покажет картинку вместо эмодзи (стили уже готовы, `object-fit: cover`).

**Как поменять тариф доставки?** В `.env`: `DELIVERY_BASE`, `DELIVERY_PER_KG`, `DELIVERY_FREE_FROM`.

**Как сбросить демо-заказы?**
```bash
sqlite3 data/shop.db "DELETE FROM order_items; DELETE FROM orders; DELETE FROM events;"
```

**Где смотреть ошибки интеграций?** В консоли сервера с префиксами `[ozon]` и `[kassa]`,
а также в таблице `events` базы.

**Безопасность.** Пароль админки сравнивается в постоянном времени, есть лимит 10 попыток входа
с одного IP за 10 минут, админ-API закрыт bearer-токеном, статика защищена от path traversal,
все SQL-запросы параметризованы. Перед боем стоит добавить: HTTPS, rate-limit на оформление заказа,
бэкапы и, при росте, Postgres вместо SQLite.
